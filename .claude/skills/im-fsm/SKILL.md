# Формальная проверка машины состояний IM

Цель — доказать, что машина состояний корректна как автомат: из начального состояния достижимо всё, тупиков нет, на каждое событие в каждом состоянии ровно один исход, ветви условий покрыты, автоматические переходы не зависят от случайностей порядка. Всё, что не так, — назвать с доказательством.

Проверка только находит и фиксирует. Машину, контракт и правила во время проверки не править: исправления идут отдельно, по плану, как у [im-review](../im-review/SKILL.md).

## Что проверяется

- Машина: `Specification/State_machine/workflow.v4.json`. JSON в чат вставлять не нужно — проверяется файл в репозитории.
- Вместе с ней: контракт `openapi.json` (обязательные поля, перечни значений), правила `Specification/State_rules/States rules IM.md` (§2, §3, §6, §9, §14.3, §14.8), перечень переходов словами `TRANSITIONS.md`.
- Исполнитель прототипа `prototype/engine.js` — только чтобы понять, как машина исполняется (порядок автоматических переходов, моменты срабатывания). Ошибки исполнителя — находки `BUG`, ошибки модели — `RULE`.

## Наша нотация

Своя, ближе всего к UML State Machine. Общий чек‑лист говорит про `states[]`, `transitions[]`, `event`, `guard`, `action`, `target` — у нас это так:

| Термин чек‑листа | В машине |
|---|---|
| состояние | `states[]`: `id`, `label`, `category`, `terminal`, `initial` (ровно у одного), `owner`, `activeTimer` |
| переход | `transitions[]`: `id`, `from[]` (несколько исходных), `to` (`null` — состояние не меняется: нарушение, алерт), `trigger` |
| событие | у ручного перехода (`trigger: manual`) событие — его `id`: оператор нажимает кнопку перехода. Автоматические (`timer`, `system`) — без события |
| guard | `guards[]` — функции из реестра `registries.guards` с аргументами; все условия перехода через «и» |
| action | `effects[]` — функции из `registries.effects`; `kind: transactional` — в транзакции перехода, `external` — после неё |
| область | `scope: incidents_owned_by_agent` — системный переход касается только инцидентов того оператора, чьё состояние проверяется |
| настройка | аргумент вида `escalation.enabled` — путь от корня машины; перечень настроек — `adminSettings`, `SETTINGS.md` |

Порядок автоматических переходов задан правилом §14.3 (RULE-41, RULE-48): из готовых первым выполняется тот, чьё условие наступило раньше (дедлайн таймера, порог молчания), переход без таймера — сразу после того, который сделал его возможным, при равенстве — порядок в `transitions[]`.

### Сравнение с общепринятыми нотациями — один раз

| | Машина IM | W3C SCXML | XState | UML |
|---|---|---|---|---|
| Начальное состояние | `initial: true` у состояния | `initial` у `<scxml>` | `initial` у машины | псевдосостояние |
| Событие | `id` ручного перехода | `event` | ключ в `on` | trigger |
| Несколько исходных у перехода | `from[]` | нет, переход внутри состояния | нет | нет |
| Условия | функции реестра через «и» | `cond` — выражение | `guard` — функция | guard |
| Действия | функции реестра, транзакционные и внешние | исполняемое содержимое | `actions` | effect |
| Переходы без события | автоматические с порядком по времени (§14.3) | eventless, по порядку документа | `always` | completion |
| Таймеры | дедлайны в данных инцидента, `timerExpired` | `<send delay>` | `after` | time event |
| Иерархия, параллельные регионы, история | нет | есть | есть | есть |
| Ошибки | отказ перехода — код `Problem` контракта (403, 409, 412) | `error.*` события | `onError` | — |

Отличий от SCXML больше трёх — это осознанное отклонение: машина — конфигурация, которую собирает редактор схемы из фиксированного реестра (§14.8), а не программа. Заново в каждом отчёте это не расписывать; упоминать, только если поменялась структура машины (появились вложенные состояния, регионы, новые виды триггеров).

### Задумано, не находка

- `closed` — терминальное, выход только `reopen` в пределах окна (§10.1, правило 4).
- Переходы с `to: null` — нарушение, алерт, потолок: состояние не меняется намеренно.
- Состояния, где автоматика молчит: после потолка эскалации или нарушения реакции инцидент ждёт человека; отложенный с истёкшим сроком — только алерт.
- Циклы `new ⇄ pending_acceptance`, `in_progress ⇄ on_hold` — выход из них — закрытие, бесконечную передачу ограничивает уровень эскалации с потолком.
- Ручное действие и таймер в один момент — выигрывает ручное (`invariants.manualWinsOverTimer`).
- Отказ перехода — не переход в «ошибочное состояние», а ответ сервера с кодом: обработчиков `onError` в машине нет и не нужно.

## Порядок

1. `git fetch`; если на GitHub есть новое — предложить подтянуть. Проверяемый коммит — `git rev-parse --short HEAD`.
2. **Скрипт.** `python3 tools/check_machine.py` и `python3 tools/build_workflow.py --check`. Его ошибки — сразу находки с пометкой ✅; пункты чек‑листа с меткой **[скрипт]** руками не повторять, только сослаться. Он же печатает карту пересечений и перебор настроек автоматических переходов: `python3 tools/check_machine.py --fsm`.
3. **Сценарии** — тесты API с названием «im-fsm: …» в [`tests/api-fsm.js`](../../../tests/api-fsm.js): один и тот же набор каждый раз — прыжок часов против шагов для пар из карты пересечений, повторный вход в «В работе» каждым переходом после истечения норматива, переходы без смены состояния — один раз на дедлайн, и покрытие: у каждого такого перехода и входа в работу есть сценарий. Запуск — тесты API: `google-chrome --headless=new --disable-gpu --no-first-run --user-data-dir=<scratchpad>/api --virtual-time-budget=120000 --dump-dom "file://$PWD/tests/api.html"`; строки «im-fsm:» из `<pre id="apitest-log">`. Их «FAIL» — находки с ✅ (пункты **[сценарий]**). Те же тесты идут в CI и против бэкенда.
4. **Таблицы.** Состояния, переходы и граф Mermaid — скриптом из файла машины, а не руками (ниже).
5. **Чтение** — пункты **[чтение]** из [checklist.md](checklist.md), по выводу вспомогательного скрипта (ниже) и названным файлам. Находку о поведении, которую сценарии не покрывают, подтвердить отдельным запуском: временная страница в scratchpad по образцу `tests/api-fsm.js` — `IMServer.create({ … testSupport: true })`, `POST /test/reset` с `workflowPatch` и `fixturePatch`, `POST /test/clock`, переходы. Временные файлы — в scratchpad, не в репозитории.
6. **Все пункты — до отчёта.** Пройти чек‑лист целиком и только потом писать находки: первая находка — не повод остановиться. Новый тип ошибки, найденный чтением, — добавить в чек‑лист, а если его можно проверить скриптом или сценарием — предложить в план такую проверку, чтобы следующий прогон находил его сам.
7. **Запись** — по правилам [im-review](../im-review/SKILL.md): если папка `reviews/<дата>/` есть — дописать проход «формальная проверка машины» в её `review.md` и `plan.md`, иначе создать. Номера сквозные (`RULE`, `BUG`, `DOC`, `PROC`), ссылки — постоянные, на проверяемый коммит. Строку в `reviews/README.md` обновить.
8. **Отчёт в чате** — формат ниже. Ничего не коммитить без просьбы. Если просят «только в чат» — шаг 7 пропустить.

### Таблицы и граф скриптом

```bash
python3 - <<'EOF'
import json, collections
w = json.load(open("Specification/State_machine/workflow.v4.json", encoding="utf-8"))
for s in w["states"]:
    kind = "initial" if s.get("initial") else "terminal" if s.get("terminal") else "normal"
    print(f"| {s['id']} | {s['label']} | {kind} |")
for t in w["transitions"]:
    event = t["id"] if t["trigger"] == "manual" else f"— ({t['trigger']})"
    guards = ", ".join(g["fn"] + (f"({', '.join(map(str, g.get('args', [])))})" if g.get("args") else "") for g in t["guards"])
    effects = ", ".join(e["fn"] for e in t["effects"])
    for src in t["from"]:
        print(f"| {src} | {event} | {guards} | {effects} | {t['to'] or src + ' (не меняется)'} |")
edges = collections.OrderedDict()
for t in w["transitions"]:
    mark = t["id"] + ("*" if t["trigger"] != "manual" else "") + ("°" if t["to"] is None else "")
    for src in t["from"]:
        edges.setdefault((src, t["to"] or src), []).append(mark)
start = next(s["id"] for s in w["states"] if s.get("initial"))
print("stateDiagram-v2\n    [*] --> " + start)
for (a, b), ids in edges.items():
    print(f"    {a} --> {b}: {', '.join(ids)}")
for s in w["states"]:
    if s.get("terminal"):
        print(f"    {s['id']} --> [*]")
EOF
```

`*` — автоматический переход, `°` — без смены состояния.

### Вспомогательный скрипт для пунктов «чтение»

Слова в идентификаторах; таблица «переход — условия — подпись — запись журнала» (говорит ли подпись то, что проверяют условия); группа сценария (выводит ли из группы переход, который меняет владельца); значения из записи журнала, которые тот же переход меняет до записи (`→пусто` — очищает); места правил вне §4, §6, §8.1, где названа функция реестра; функции сверх базового реестра без описания.

```bash
python3 - <<'EOF'
import json, collections
w = json.load(open("Specification/State_machine/workflow.v4.json", encoding="utf-8"))
words = collections.Counter(p for t in w["transitions"] for p in t["id"].split("_"))
print("Слова в идентификаторах переходов:", dict(words))
for t in w["transitions"]:
    guards = ", ".join(g["fn"] + (str(g["args"]) if g.get("args") else "") for g in t["guards"])
    logs = [e["args"][0] for e in t["effects"] if e["fn"] == "appendLog"]
    print(f"| {t['id']} | {guards} | {t['label']} | {' / '.join(logs) or '—'} |")
print("Группа сценария: переход | меняет владельца | clearGroup | режим выборки")
for t in w["transitions"]:
    fns = [e["fn"] for e in t["effects"]]
    if "setOwner" in fns or t["to"] == "new":
        print(f"| {t['id']} | {'да' if 'setOwner' in fns else 'нет'} | {'да' if 'clearGroup' in fns else 'НЕТ'} | {(t.get('bulk') or {}).get('mode', '—')} |")
import re
CHANGES = {"targetName": {"setOwner", "setAssignmentGroup"}, "escalationLevel": {"increment:escalation_level", "setFlag:escalation_level"},
           "holdReasonLabel": {"setHoldReason", "clearHoldReason"}, "closeResultLabel": {"setFlag:close_result"}, "stepNumber": {"setCursor"}}
print("Запись журнала: переход | переменная | меняется в том же переходе до записи")
for t in w["transitions"]:
    fx = [(e["fn"] + (":" + e["args"][0] if e["fn"] in ("setFlag", "increment") else ""),
           e["fn"].startswith("clear") or (e["fn"] in ("setFlag", "setOwner") and e["args"][-1] is None)) for e in t["effects"]]
    for i, e in enumerate(t["effects"]):
        for v in re.findall(r"\{(\w+)\}", e["args"][0]) if e["fn"] == "appendLog" else []:
            before = [f + ("→пусто" if empty else "") for f, empty in fx[:i] if f in CHANGES.get(v, ())]
            if before:
                print(f"| {t['id']} | {{{v}}} | {', '.join(before)} |")
fns = {g["fn"] for g in w["registries"]["guards"]} | {e["fn"] for e in w["registries"]["effects"]}
print("Правила вне §4, §6, §8.1: строка | раздел | функции реестра")
sec = ""
for n, l in enumerate(open("Specification/State_rules/States rules IM.md", encoding="utf-8"), 1):
    if l.startswith("#"):
        sec = l.strip("# \n").split(" ")[0]
    named = sorted(f for f in fns if f"`{f}" in l)
    if named and not sec.startswith(("4.", "6.", "8.1")):
        print(f"| {n} | §{sec} | {', '.join(named)} |")
print("Сверх базового реестра без $comment:", [e["fn"] for k in ("guards", "effects") for e in w["registries"][k] if e.get("extendsBaseRegistry") and not e.get("$comment")])
EOF
```

## Важность

Уровни общего чек‑листа переводятся в наши:

| Чек‑лист | Ревью IM | Когда |
|---|---|---|
| critical | [блокер] | машина не загружается, JSON невалиден, начальных состояний не одно |
| major | [высокий] или [средний] | нарушена достижимость, детерминизм, тупик без `terminal`, условия пересекаются или не покрыты; [высокий] — если тихо теряются данные (нарушение пропадает, инцидент застревает) |
| minor | [низкий] | стиль, именование, типы без влияния на поведение |

## Отчёт в чате

1. **Сводка** — корректна ли машина; сколько находок какой важности; что подтверждено скриптом и сценариями.
1а. **Таблица покрытия** — каждый пункт [checklist.md](checklist.md): чем проверен (скрипт, сценарий, чтение) → результат (без замечаний / находка / не проверяется статически). Без неё отчёт не полный.
2. **Таблица состояний**: id | название | вид (initial / normal / terminal).
3. **Таблица переходов**: from | событие | условия | эффекты | to. Длинную — свернуть по `from`.
4. **Таблица проблем**: проблема | место в машине (путь, состояние, переход) | важность | уверенность (высокая / средняя / низкая — и почему) | что предложено.
5. **Граф** Mermaid `stateDiagram-v2`: `[*]` для начального и терминальных, метки — идентификаторы переходов.
6. **Предлагаемые правки** — «было → стало» по фрагментам машины. В репозиторий не вносить: предложения идут в `plan.md`.
7. **Что не проверяется статически** — с причиной: права и роли из внешней системы, время и связь оператора, внешние эффекты, машина сценариев, бизнес-смысл значений.

Перед ответом — самопроверка: все пункты [checklist.md](checklist.md) закрыты; у каждого вывода есть доказательство (путь в графе или контрпример) и уверенность; нет ссылок на поля, которых в машине нет; вердикт не противоречит таблице проблем.
