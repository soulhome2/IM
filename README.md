# Incident Manager (МИ)

Проработка нового приложения **Axxon Incident Manager** — рабочего места оператора для обработки инцидентов от систем видеонаблюдения и охраны. Репозиторий содержит продуктовые документы и работающий прототип интерфейса оператора.

Всё содержимое — материалы этапа проектирования: требования, правила жизненного цикла инцидента и кликабельный прототип для согласования. Production-кода здесь нет.

## Прототип

| Файл | Что это |
|---|---|
| [prototype/index.html](prototype/index.html) | Рабочее место оператора: очередь инцидентов, карточка обработки по сценарию, видеомонитор и карта. Открывается двойным кликом, сборка и сервер не нужны |
| [prototype/app.js](prototype/app.js) | Вся логика и демонстрационные данные: состояния инцидентов, сценарии обработки, права, передача, эмуляция работы коллег |
| [prototype/styles.css](prototype/styles.css) | Оформление, светлая и тёмная темы, адаптивные раскладки |
| [prototype/bridge.css](prototype/bridge.css) | Restyle в семью ONE PSIM: маппинг на [theme/one-psim.css](theme/one-psim.css), без правок разметки и JS. Как смотреть и что подтвердить — [prototype/README.md](prototype/README.md) |

### Что показывает прототип

Очередь с фильтрами и группировкой по объектам, взятие инцидента в работу, пошаговый сценарий обработки с обязательными шагами, приостановку и возобновление, передачу с выбором адресата, перехват чужого инцидента, групповую обработку, нормативы реакции с обратным отсчётом, перерыв оператора, горячие клавиши, светлую и тёмную темы. Видеомонитор и планы объектов нарисованы примерами прямо в файле, поэтому прототип работает без сервера и без доступа к камерам.

### Как связаны документы

Видение задаёт требования. Правила превращают их в жизненный цикл инцидента. Как правила к этому пришли, видно по архиву: первая версия, её разбор с противоречиями, вторая версия, которая их устраняет, третья, где «Эскалация» и «Перенаправить» слились в одну передачу, четвёртая с закрытием без сценария для массовых сбоев.

Машина состояний — те же правила в виде конфигурации, которую исполняет сервер, и API для клиента. Прототип исполняет её прямо в браузере (`prototype/engine.js`): своей таблицы переходов у него нет, поэтому прототип и машина не расходятся.

Прототип сделан по четвёртой версии и доведён до решений ревью 2026-10-01. Где он отступает от правил — в §17 правил.

## Термины

Полный словарь с расшифровкой сокращений — в §1 [правил](Specification/State_rules/States%20rules%20IM.md). Коротко: **МИ** — менеджер инцидентов, **SLA** — отведённое время на реакцию и на закрытие инцидента, **сценарий** — пошаговая инструкция обработки под тип события, **передача** — отдать инцидент адресату (своё или чужое — одно действие, разные права), **закрытие без обработки** — закрыть без сценария по праву, **автоэскалация** — системная передача по таймеру, **перехват** — изъятие инцидента у работающего оператора.

## Как посмотреть прототип

Откройте `prototype/index.html` в браузере. Нужен интернет — из сети подгружаются шрифты Inter и Material Symbols; без него всё работает, но иконки будут показаны текстом.

Полезное при первом запуске:

- `?` — список горячих клавиш;
- `F1` — регламент обработки инцидента;
- кнопка солнца в правом верхнем углу — переключение светлой и тёмной темы;
- меню оператора справа сверху — перерыв и предвыбор адресата передачи;
- через 10–30 секунд коллеги начнут разбирать события из очереди — так видно поведение чужих инцидентов и работу перехвата.

## Проверки

- `prototype/index.html?selftest` — самопроверка: прототип сам проходит основные переходы (взять, закрыть, отложить, передать, принять и другие) и показывает отчёт. После прогона демо-данные во вкладке изменены — для чистого прототипа откройте страницу без `?selftest`.
- `python3 tools/build_workflow.py` — собрать `prototype/workflow.js` из машины после её правки. `--check` — проверить, что файл не отстал (так делает CI).
- `python3 tools/check_machine.py` — целостность машины состояний: переходы ссылаются на существующие состояния, формы, условия, эффекты, права и таймеры, API совпадает с моделью. Смысл правил не проверяет.
- `python3 tools/check_mutations.py` — правила только в машине: в копии прототипа по одному меняются правила машины, и проверяется, что прототип ведёт себя по-новому. Если нет — правило продублировано в коде прототипа. Около полутора минут.
- `python3 tools/check_links.py` — нерабочие ссылки в документах.
- На GitHub все проверки запускаются на каждый push. Результат — значок у коммита и вкладка Actions.
