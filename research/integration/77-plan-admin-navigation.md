# План: перегруппировка вкладок конфигуратора

> **Для исполнителя-агента:** выполнять по задачам через superpowers:subagent-driven-development или superpowers:executing-plans. Шаги отмечаются `- [ ]`.

**Цель:** вместо 19 вкладок на трёх уровнях — 5 вкладок наверху, внутри каждой 2–4. Вкладки идут в порядке настройки поста, так что администратор не упирается в ненастроенное. Плюс четыре удобства: ссылки между связанными местами, счётчик «где используется», свой адрес у каждой вкладки, страница «Готовность поста».

**Репозитории:** IM (машина, строки, прототип), `~/Work/incident-manager` (конфигуратор), при нужде `~/Work/incident-manager-server`; ветка `feature/im_operator`. Коммиты — только по просьбе. Перед коммитом конфигуратор собирается на стенд.

## Решения (2026-11-10)

- **1.** Вариант A: группировка по задачам администратора.
- **2.** Порядок — как настраивают пост: **Источники → Люди → Реагирование → Настройки поста → Журналы**. Частоту использования закрывает запоминание последней вкладки.
- **3.** «Связи камер» — вкладка сразу, пустая, с одной строкой-пояснением; список — с видео (этап 10).
- **4.** Перенаправлений со старых адресов нет: продукт не выходил, старыми адресами никто не пользовался.
- **5.** «Справочники» убираются: приоритеты — в «Реагирование» последней вкладкой, справочные ссылки — в «Настройки поста → Работа оператора».

| Журналы | События · Действия · Изменения настроек | `/logs/events`, `/logs/actions`, `/logs/settings` |

Состав «Настроек поста» — из вкладок машины:

| Новая вкладка | Прежние вкладки машины |
|---|---|
| Сроки и эскалация (`timing`) | `norms`, `escalation` |
| Работа оператора (`operator`) | `queue`, `limits`, `session`; справочные ссылки (`links`) |
| Причины (`reasons`) | `reasons` |
| Хранение и резервная копия (`storage`) | `retention`, статистика базы, резервная копия |

Внутри объединённой вкладки прежние вкладки — разделы с заголовками, в том же порядке.

## Общие ограничения

- Вкладки «Настроек поста» и подписи — из `adminSettings.tabs` машины; своего списка у клиента нет. Объединение — правкой машины в IM, не в конфигураторе.
- `src/operator/` не трогать.
- «Журналы» видны только с правом `incident_manager.manage` — как сейчас «Журнал событий» и «Аудит».
- Тексты — ru, en, kk, zh; ключа без перевода нет.
- Проверки конфигуратора: `npx vitest run`, `npx tsc -b`, `npx eslint` по затронутым файлам.
- Проверки IM после правки машины — по таблице CLAUDE.md: сборка, `check_machine.py`, самопроверка прототипа, `check_ui.py`, `check_guide.py`, `cel_vectors.mjs --update`.

## На что смотреть при проверке

1. Наверху ровно 5 вкладок в порядке решения 2; без права `manage` — 4.
2. Каждая вложенная вкладка открывается по своему адресу; обновление страницы оставляет на ней.
3. Вход без адреса — на последнюю открытую вкладку; первый вход — на «Источники → Группы устройств».
4. «Связи камер» — строка-пояснение, не пустота и не ошибка.
5. Все настройки машины по-прежнему видны и в конфигураторе, и в окне администратора прототипа; `check_machine.py` не нашёл настройки вне перечня.
6. В «Правилах» без групп устройств — подсказка со ссылкой на «Источники».
