# План: резервная копия настроек МИ в файле

> **Исполнено 2026-11-10.** `getLastBackup`, таблица `config_backups` и «Вернуть как было» не делались — решение пользователя; миграция 058 только расширяет журнал настроек.

> **Для исполнителя-агента:** выполнять по задачам через superpowers:subagent-driven-development или superpowers:executing-plans. Шаги отмечаются `- [ ]`.

**Цель:** администратор в конфигураторе сохраняет все объекты и настройки МИ в файл и восстанавливает их из файла: по GUID, с предпросмотром, резервной копией и одной транзакцией.

**Устройство:** четыре метода в контракте оператора. На сервере:
- `Snapshot` читает состояние заказчика;
- чистая функция `Plan(cur, file, refs)` сравнивает его с файлом по GUID;
- `Apply` исполняет план в транзакции.

Конфигуратор показывает план. Эмулятор загружает тестовые наборы тем же API.

**Стек:** контракт `Specification/Workflow_machine/openapi.json` (IM) → `openapi.v30.json` → `make` на сервере (oapi-codegen). Go, gin, PostgreSQL. Конфигуратор — React, MUI, react-query, vitest.

**Проект:** [75-config-export-import.md](75-config-export-import.md) — по нему решаются все спорные места.

**Репозитории:** IM, `~/Work/incident-manager-server`, `~/Work/incident-manager`, ветка `feature/im_operator`. Коммиты — только по просьбе. Перед коммитом сервер и конфигуратор собираются на стенд.

## Общие ограничения

- Все четыре метода — право `incident:schema:admin` (`adminRight` в `internal/im/handler/operator/admin.go`), без права — 403 `PERMISSION_DENIED`.
- Заголовок: `{"format":"im-backup","version":1,"customerGuid":…}`. Чужой `format`, `version` > 1 или чужой `customerGuid` — 400 до любых сравнений.
- Сравнение — только по GUID. Состав разделов — по таблице «Что входит в файл» проекта 75.
- Ключи агентов в файл не пишутся, восстановление их не трогает.
- Объект, на который ссылаются инциденты или события, не удаляется: только «оставлено».
- Применение: резервная копия, восстановление и запись аудита — одна транзакция.
- `openapi.json` и `Specification/Workflow_machine/README.md` — в CRLF.
- Тексты интерфейса — ru, en, kk, zh.

## На что смотреть при проверке

1. **Экспорт, затем сразу загрузка того же файла.** План пуст, база не изменилась. Тест — задачи 3 и 4.
2. **Удалили правило, группу и устройство, затем загрузили файл.** Все три вернулись с прежними GUID; правило снова создаёт инциденты; группа в правиле доступа снова видна. Тест — задача 4.
3. **После экспорта создали инцидент с новым приоритетом, затем загрузили файл.** Приоритет «оставлен», инцидент открывается. Тест — задачи 3 и 4.
4. **Ошибка посреди применения** (битый `script` сценария, не проходит проверку машины). Откат всего, резервная копия прежняя. Тест — задачи 4 и 4б.
5. **Настройки поменялись между предпросмотром и применением.** 409 «повторите предпросмотр». Тест — задача 4.
6. **В файле нет секретов.** В экспорте нет полей `agent_api_keys` и токенов регистрации. Тест — задача 2.

### Задача 1: контракт

**Файлы:** `Specification/Workflow_machine/openapi.json` (IM), затем `python3 tools/build_workflow.py`, затем `make` в сервере.

**Даёт** (тег `admin`):

| operationId | Метод | Тело → ответ |
|---|---|---|
| `exportBackup` | `GET /admin/backup` | → `BackupFile` (`Content-Disposition: attachment; filename=im-backup-<дата>.json`) |
| `previewRestore` | `POST /admin/backup/preview` | `BackupFile` → `RestorePlan` |
| `applyRestore` | `POST /admin/backup/apply` | `{file, planHash, fileName}` → `RestorePlan` (что сделано) |
| `getLastBackup` | `GET /admin/backup/last` | → `BackupFile` (копия перед последней загрузкой); 404 — копии нет |

`RestorePlan`:
- `hash`;
- `sections[]` — `{section, restore[], update[], delete[], kept[]}`, каждый элемент — `{guid, name}`;
- `workflow` — `{changes, openIncidents}`, есть только при разделе в файле.

`BackupFile`: заголовок плюс разделы по таблице проекта 75. Строки разделов — объекты со столбцами таблиц в camelCase. Поле `script` и заплатка машины — объекты без внутренней схемы.

- [ ] Проверки IM: `build_workflow.py --check`, `test_openapi30.py`, `check_links.py`. Сервер: `make`, `go build ./...`.

### Задача 3: сервер — план восстановления

**Файлы:** `internal/im/service/backup/plan.go`, `plan_test.go`.

**Даёт:**
- `Plan(cur, next *File, refs Refs) *RestorePlan` — чистая функция;
- `Refs` — какие GUID приоритетов, статусов и сценариев заняты инцидентами или событиями; число открытых инцидентов;
- `LoadRefs(ctx, tx, customer)`;
- `Hash(cur, next)` — sha256 канонического JSON.

Таблица случаев:
- [ ] Тот же файл — все списки пусты.
- [ ] Строка есть только в файле — `restore`; есть в обоих, но различается — `update`; есть только в базе — `delete`.
- [ ] Только в базе и занята историей — `kept`, не `delete`.
- [ ] Версия сценария, которая есть в обоих, не попадает в `update`, даже если различается: существующие версии неизменны.
- [ ] `workflowSettings` отличается — `workflow.changes = true`, `openIncidents` верно; раздела нет — `workflow` нет.
- [ ] Обработчик предпросмотра: 403 без права; 400 на чужой `format`, на `version: 2` и на чужой `customerGuid`.

### Задача 4: сервер — восстановление, резервная копия, аудит

**Файлы:** миграция `058_backups.sql` — таблица `config_backups(customer_guid PK, body JSONB, created_at, created_by)`; `internal/im/service/backup/apply.go`; обработчики в `backup.go`.

**Даёт:** `Apply(ctx, tx, customer, user, next *File, planHash, fileName) (*RestorePlan, error)`. Внутри одной транзакции:
1. `Snapshot`, `LoadRefs`, `Plan`.
2. Хэш не совпал — `ErrStale` (409).
3. Upsert в `config_backups`.
4. Применение по разделам:
   - порядок по внешним ключам: агенты → типы → события → устройства → группы (родители раньше детей) → состав → приоритеты и статусы → сценарии → правила → доступ → дежурные → ссылки;
   - удаление в обратном порядке;
   - устройства, типы и агенты — `deleted_at`, а не удаление;
   - вставка с GUID из файла (`INSERT … ON CONFLICT (guid) DO UPDATE`, со снятием `deleted_at`).
5. Запись аудита настроек `backup.restore`.

Тесты (тестовая база, как `internal/im/handler/test`):
- [ ] Экспорт → удалить правило, группу, устройство → применить экспорт: все вернулись с прежними GUID. Событие на устройство снова создаёт инцидент по правилу.
- [ ] Экспорт → применение того же файла → экспорт: файлы равны.
- [ ] Битый `script` во втором сценарии — ошибка; база и `config_backups` как до вызова.
- [ ] `ErrStale` — 409.
- [ ] Инцидент с приоритетом, созданным после экспорта: после восстановления приоритет на месте, инцидент открывается.
- [ ] `getLastBackup`: до первой загрузки — 404, после — состояние до неё.
- [ ] Ключ агента после восстановления прежний, вход по HMAC работает.
- [ ] Миграции вверх и вниз.
