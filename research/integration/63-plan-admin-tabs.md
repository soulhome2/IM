## Global Constraints

- Репозиторий `~/Work/incident-manager`, ветка `feature/im_operator`; `src/operator/` (место оператора) не трогать.
- Адрес API — `/api/v1/im-backend` через `apiFetch` из `@/shared/api/http`, как у соседних фич; ответы разбираются zod-схемами.
- Тексты интерфейса — в `src/shared/i18n/locales/{ru,en,kk,zh}/`, все четыре языка; ключа без перевода нет.
- Названия и описания приоритетов — данные (`LocalizedText`: `ru` обязателен, остальные языки — по желанию), они не переводятся.
- Цвет — только из палитры контракта `PriorityColor`: `red`, `amber`, `blue`, `grey`; цвет показан и квадратиком, и словом.
- Ошибки сервера показываются пользователю, не глушатся: `403 PERMISSION_DENIED`, `409 PRIORITY_EXISTS`, `409 PRIORITY_IN_USE`, `422 FORM_FIELD_INVALID` (с `details.field`) — каждая своим понятным текстом.
- Экранный диктор не поддерживается (решение 2026-10-17).
- Проверки конфигуратора: `npx vitest run`, `npx tsc -b`, `npx eslint` по затронутым файлам — без ошибок.

## Review Focus

- Удаление уровня, который носят открытые инциденты или правило, — `409 PRIORITY_IN_USE`: строка остаётся, пользователь видит причину.
- Число у существующего уровня не меняется (`PriorityChange` без `value`): в форме правки поле числа только для чтения.
- Повтор названия `ru` — `422` с `details.field: "name.ru"`: ошибка у поля названия, форма не закрывается.
- Нет права `incident:schema:admin` — `403`: список виден, кнопки правки дают понятный отказ, а не пустоту.
- После любой правки список перечитывается (`GET /operator/reference/priorities`): правила инцидентов, где выбирается приоритет, видят новый уровень.
