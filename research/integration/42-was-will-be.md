# Как МИ создаёт инциденты из событий: было и будет

Для коллег, коротко. Решения пользователя от 2026-10-28; подробности — [41-multi-service.md](41-multi-service.md) и проект [design-1b.md](../../reviews/2026-10-28/design-1b.md).

## Было

- Одно событие порождает **один инцидент** с **одним сценарием**.
- Приоритет инцидента присылает **источник события**.
- Если событие подходит под несколько правил, выбирается одно.

## Будет

- Событие проходит через **фильтры (правила)**. У каждого фильтра свой сценарий и свой приоритет.
- **Каждый сработавший фильтр создаёт свой инцидент.** Одно событие может дать несколько инцидентов: например, пожар — инцидент для пожарной службы и инцидент для медпункта.
- **Повторов нет.** Если два фильтра ведут к одному сценарию, создаётся один инцидент, а правило для него выбирается по точности условия.
- **Приоритет задаёт правило**, а не источник.
- **Номер тревоги.** У всех инцидентов одного события общий номер тревоги — это номер первого из них, например «тревога INC-1852». По этому номеру находятся все инциденты тревоги.
- **Соседи видят друг друга.** В карточке есть блок «По этому событию: INC-1853 — Медпункт, в работе», в очереди — отметка «ещё N». Видны только те соседи, к которым у оператора есть доступ.
- **Закрытие независимо.** Закрытие одного инцидента не закрывает соседние. Если инцидент закрыли как «Ложную тревогу», ответственному за соседний приходит уведомление.
- **«Дубликат».** Закрыть инцидент «Дубликатом» можно, но если у него есть соседи, форма предупредит: это другие службы той же тревоги, а не дубли.
- **«Массовый сбой» на выборке** закрывает только инциденты своего сценария, остальные пропускает и показывает, какие именно.
- **Звук** — один на тревогу, а не на каждый инцидент.
- **Нормативы** реакции и закрытия можно задать для каждого сценария.
- **Фильтр очереди по сценарию** — чтобы каждая служба видела своё.

## Позже, не сейчас

- Адресовать инцидент сразу дежурной группе службы.
- Своя цепочка эскалации для каждой службы.
