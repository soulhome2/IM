# Этап 9: экраны оператора — план работ

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task (проверка по группам, см. раздел «Порядок проверки», выбрано пользователем 2026-11-01). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** на странице `/im/operator/` работают очередь, карточка с обработкой по сценарию, передача, отложение, перерыв и выборка: сначала на встроенном сервере прототипа, затем на сервере МИ, и сценарий руководства оператора проходится от события эмулятора до закрытия.

**Architecture:** Всё — в `src/operator/` конфигуратора, на клиенте этапа 8. Данные — запросы контракта через `OperatorTransport` и TanStack Query, состояние экрана — один store zustand, оформление — тема MUI из токенов ONE PSIM. Правил в экранах нет: кнопки, формы, бейджи, фильтры и тексты приходят из ответов API и активной схемы. Проигрыватели шагов — общий модуль `features/step-player`.

**Tech Stack:** React 19, TypeScript, Vite 8, Vitest 4, jsdom, Testing Library, MUI 9, TanStack Query 5, zustand 5, zod 4, i18next, nanoid, puppeteer-core (только `~/Work/stand/ui-check`). Новых зависимостей нет.

**Spec:** [40-plan.md](40-plan.md), этап 9, решения 3 и 6; `Specification/Workflow_machine/FRONTEND.md` — входной документ: что требование, а что только демо; `Specification/Interface/SITEMAP.md`, `DESIGN_SYSTEM.md`; `Specification/Operator guide.md`; `Specification/Workflow_machine/openapi.json`, `workflow_schema.v1.json`; `prototype/app.js`, `styles.css`, `bridge.css`, `index.html`, `prototype/shots/`; [58-plan-stage8.md](58-plan-stage8.md), раздел Interfaces и передача этапу 9.

## Review Focus

1. **Оператор печатает, а поток перечитывает карточку.** Коллеги и таймеры шлют события каждые секунды, каждое перечитывает карточку. Ждём, что введённое в шаг или открытую форму не пропадает и фокус остаётся в поле. Тест — Task 13б, `keeps the draft while the card is re-read`; Task 10, `keeps the open form while the incident is re-read`.
2. **Двойное нажатие и гонка двух операторов.** Двойной щелчок по «Взять» или два оператора на одном инциденте. Ждём один запрос от этого окна, а при `412` — причину и свежую карточку без ошибки на весь экран. Тест — Task 8, `sends one request on a double click`, `shows the reason and the fresh card on 412`.
3. **Поток молча умер.** Сеть мигнула, шлюз закрыл соединение, сервер перезапустился. Экран дежурного не должен тихо устареть. Ждём переподключение с `Last-Event-ID`, перечитывание и строку «Нет связи с сервером», пока связи нет. Тест — Task 17а, `re-reads after a reconnect`, `retries on a gateway error`; Task 17б, `shows a lost connection line`.
4. **Сервер прислал незнакомое.** Новый стиль кнопки, бейдж, значок, приоритет вне справочника, тип шага из новой версии. Ждём обычную кнопку и строку, а не белый экран. Тест — Task 5б, `renders a row with unknown style, badge and priority`; Task 8, `falls back to outline`; Task 13б, `shows a plain line for an unknown step type`.
5. **Часы пульта врут.** Пульт спешит на две минуты. Ждём остаток по времени сервера, а не «просрочено». Тест — Task 5а, `counts down by server time when the console clock runs ahead`.

- **144.** Старшинство: правила и машина, затем прототип, затем `SITEMAP.md` и `DESIGN_SYSTEM.md` (сами документы так и говорят: верен CSS, верен прототип). `FRONTEND.md` решает, что требование, а что демо. Код прототипа читается как описание поведения, в продукт не копируется: это `innerHTML` на 4400 строк, у него другая модель. Функции прототипа названы в задачах, чтобы было где смотреть поведение.
- **145.** Порядок — все экраны на встроенном сервере, потом настоящий. Почему: поведение встроенного проверено 91 шагом самопроверки, а на настоящем до этапа 7 нет схемы и строк. Страница не меняется: `pickApiMode` этапа 8 уже выбирает транспорт.
- **146.** Роутера нет. Это закрывает передачу из решения 120. `SITEMAP.md`: «одна страница без адресов разделов», прототип так и работает. Обновление страницы возвращает к очереди, инцидент остаётся за оператором, ничего не теряется. Глубокая ссылка из этапа 8 открывает очередь. Цена: кнопка браузера «Назад» уводит со страницы, это поведение прототипа.
- **147.** Данные сервера — TanStack Query, состояние экрана — один store zustand на страницу, через `createWorkplaceStore()` и контекст, чтобы тест имел свой. `retry: false` (кроме потока), `refetchOnWindowFocus: false`, `staleTime: 0`. Свой `QueryClient` у страницы, не общий с конфигуратором. Почему: оба уже в проекте; `invalidateQueries` даёт поведение `reload()` прототипа, включая «запрос во время загрузки не теряется». Отметки, черновики и версии — обычные массивы и объекты: `Set` и `Map` в store не кладём.

*Тема*

- **148.** `theme/one-psim.css` копируется в `src/operator/theme/one-psim.css` без правок, тема — `createOperatorTheme(mode)`. Токены читаются как CSS-переменные. Для палитры MUI нужны настоящие цвета: `alpha` и `lighten` не понимают `var()`. Поэтому `tokens.ts` держит около 20 значений обеих тем, а тест сверяет их с CSS без учёта регистра цвета: две записи одного значения не разойдутся. Тест лежит в `tests/` и читает файл через `node:fs`: `?raw` в Vitest отдаёт пустую строку (Task 1, Step 1). Копия закрыта от хука в `.prettierignore`. Тема не идёт через `@/theme`: та задаёт OEM конфигуратора, а решение 6 плана 40 выбрало ONE PSIM. Поэтому `OperatorRoot` не использует `MuiLocaleProvider`: он поставил бы сверху `@/theme`, а тест на `createOperatorTheme` этого не заметил бы. `OperatorThemeProvider` сам строит `createTheme(createOperatorTheme(mode), muiLocaleForLanguage(i18n.language))`, проверка — на рендере. Страницы этапа 8 (нет прав, конец сессии) получают ту же тему.
- **149.** Тема — `data-theme` на `<html>`, ключ `im-theme`, по умолчанию тёмная, как у прототипа. `preferences.theme` не используем: прототип его тоже не использует. Смысловые цвета, которых нет в словаре, — в `src/operator/theme/operator.css`, префикс `--op-`, значения из `bridge.css`: `--op-transfer-bg`, `--op-transfer-hover`, `--op-transfer-text`, `--op-foreign-bg`, `--op-foreign-text`. Переменные прототипа (`--bg`, `--accent`) не переносим: `DESIGN_SYSTEM.md`, раздел 13.
- **150.** `operator/index.html` получает те же ссылки на Inter, что корневой `index.html`. Решение 141 это запрещало этапу 8, потому что там нечего было сравнивать; здесь без Inter снимки не сравнить. Отличие принято: прототип грузит `Inter:opsz@14..32`, конфигуратор `Inter:wght@400;500;600;700`, толщина 600 у прототипа может быть синтезированной; запись в `progress.md`. Без сети значки прототипа станут текстом, поэтому `height` пар со значками смотрим только при доступных шрифтах. Material Symbols не подключаем: значки — `@mui/icons-material`, по файлу на значок. Имя значка от сервера (`visibility`) проходит закрытую таблицу `src/operator/ui/serverIcon.ts`; незнакомое имя — значок `HelpOutline`.

*Машина и экраны*

- **151.** В `src/operator/**` нет имён состояний, переходов, причин, результатов и прав. Кнопки — `actions` строки, карточки, выборки; формы — `forms` схемы, поля — `fieldOptions`, `fieldRules`, `formNote`; бейдж — `badge`; пояснение — `note`; фильтры и порядок — `queueFilters`, `queueSort`; лимиты — `limits`. Фильтр по умолчанию — первый в `queueFilters`. Перечисления контракта (`ownership`, `stateCategory`, `Badge.style`, `agentState`, `kind`) разрешены: это формат ответа, не правило. Но их значения совпадают с именами машины (`linked`, `new`), поэтому такие значения допустимы только в коротком списке файлов внутри теста. Следит тест `tests/operator-no-rule-names.test.ts`, Task 8: запрещённые имена он берёт из копии машины, а не из списка руками.
- **152.** Закрытие — без буквального `close`. Результат полной обработки — пункт каталога с `finish: true`. Закрывающий переход — тот, у формы которого есть поле с `source` на каталог с таким пунктом: `closingTransitionId(workflow)`. Кнопка такого перехода подписана «Закрыть без обработки», в её форме пункта с `finish` нет, «Завершить инцидент» шлёт его же с этим результатом. Почему: `FRONTEND.md` требует две кнопки одного перехода, а правка машины не должна ломать интерфейс.
- **153.** Уведомления после перехода — единственное место с именами переходов: таблица `src/operator/forms/transitionToasts.ts`, как `TOASTS` прототипа. Тест из решения 151 разрешает только этот файл. Неизвестный переход — подпись перехода и номер. Почему: текстов уведомлений в машине нет, а вид одного уведомления не правило.
- **154.** Обязательность шага, заполненность ответа и доступность «Далее» считает `src/operator/card/scenarioView.ts`. Это формат сценария, раздел 9 спецификации, а не правила машины: так делает прототип, и окончательно решает сервер. Что дальше после ответа считает только сервер. JSONLogic на клиенте оператора нет.
- **155.** Переходы кнопок всегда идут по действию из ответа сервера. Недоступная кнопка — `aria-disabled="true"`, а не `disabled`: нажатие показывает причину уведомлением, форма не открывается. Причина — `reasonKey` с `reasonVars`, запасной вариант `reason`.

*Тексты*

- **156.** Тексты машины — каталог `GET /operator/strings?locale=`, ключ `ключ → ICU`. Оба языка грузятся при старте, как у прототипа: язык меняется без запроса. ICU разбирает своя функция `formatIcu`: `{x}`, `{n, plural, …}`, `=N`, `#`. `select` в каталоге нет (проверено на 428 ключах языка), `intl-messageformat` ради этого не берём. Ответ операции — `{locale, strings}`, `getStrings` разворачивает `.strings`: плоский словарь в подделке дал бы зелёные тесты и пустой экран. Нет ключа — показать запасной готовый текст ответа (`label`, `reason`, `message`, `text`), нет и его — пустую строку. Ключ на экран не выводится.
- **157.** Тексты самого интерфейса — пространство `operator` этапа 8, ru и en. Значения берутся из словарей прототипа: `i18n-ui.js`, `i18n-html.js` (русский — ключ словаря, английский — значение). Требование `FRONTEND.md` перенести их в каталог (PROC-15) потребовало бы правки сервера и строк IM, это вопрос 2 ниже. Формы после чисел — `_one`, `_few`, `_many`, `_other`.
- **158.** Языков интерфейса два, как у прототипа. Порядок выбора: `im-lang`, затем `session.preferences.locale`, затем `i18n.language` из `/me`; не `ru` и не `en` — `en`. Смена языка: `i18n.changeLanguage`, запись `im-lang`, `PATCH /operator/session/preferences {locale}`, перечитывание. Названия, введённые людьми, не переводятся: `i18n-data.js` не переносится, поэтому на английском набор показывает русские названия.

*Сеть*

- **159.** Типы контракта пишутся руками в `src/operator/api/contract.ts`, только читаемые поля, и лежат в одном файле. Генератор — новая зависимость. Схемой zod проверяются только `session` (этап 8) и `workflow`: без них экран не строится. Версия для `If-Match` — `"${card.version}"`, ключ повтора — `nanoid()` на каждое действие (сервер принимает до 200 символов). `ETag` не читаем: версия есть в теле.
- **160.** Поток идёт через `apiFetch`, а не через `getFreshAccessToken`, как предполагало решение 139. Причина: `apiFetch` сам берёт свежий токен, а ветка 401 и отметка конца сессии достаются бесплатно. Заголовки `Accept: text/event-stream`, `Last-Event-ID`. Разбор — чистая функция, кадр из одного `id:` только сдвигает `lastEventId`, комментарий пропускается. Обрыв: пауза 1 с, удвоение до 15 с, сброс после первого принятого байта. Ответ не `2xx` без тела (шлюз вернул 502, 503) — такой же обрыв: `apiFetch` вернёт `Response`, а не исключение. На сроки обновления токена поток не опирается: `apiFetch` может ждать пару до `ATTEMPT_DEADLINE_MS` (8,5 с, этап 8), это ожидание ответа, а не обрыв, строка о связи появится только после него. После любого переподключения — перечитывание (BUG-102). `isSessionEnded()` — выход из цикла. Транспорт поток не проходит: решение 139 оставлено, тип `OperatorStream` отдельный.
- **161.** Оговорка из решения 130 не закрывается: второй 401 сервера МИ при сбое обращения в облако покажет ложный экран конца сессии. Пользователь оставил вход и токены как есть, правка `http.ts` запрещена. Вопрос 3 ниже. Случай редкий: нужны два плохих ответа подряд при рабочем обновлении токена. Обновление страницы лечит, только когда связь сервера МИ с облаком вернулась; до этого каждая перезагрузка кончается тем же экраном. Несохранённый ввод при этом теряется.
- **162.** Признак активности — раз в `session.heartbeatSec` и сразу при смене открытой карточки, в `openIncidentGuid` идёт guid только при `mode === 'work'`. Это **отступление от прототипа**: он шлёт выбранную строку и в очереди. Контракт: «какая карточка сейчас открыта»; иначе выбранная строка ловила бы `incident.card_evicted`. Режим `offline` — без признака: оператор вышел.
- **163.** Загрузка делит запросы на обязательные и необязательные. Обязательные: сессия, схема, каталоги двух языков, приоритеты, адресаты. Без них экран не строится, и показывается `operatorBoot.failed` с кодом и именем операции. Необязательные: дерево, типы устройств и событий, сценарии, справка. Отказ убирает только свой элемент экрана. Пустой список адресатов на 200 — не отказ. Почему: так часть 4 покажет, чего не хватает, а не упадёт. Схема и приоритеты с самого начала живут в запросах `QK.workflow`, `QK.priorities`: Task 17б только инвалидирует их, а хук, от которого зависят все экраны, не переделывается. Обязательная `getActiveWorkflow` не входит в семь отложенных операций схем.

*Экраны*

- **164.** Видео и карты нет: нет колонки, кнопки в шапке, разделителей `splitMedia`, `splitVideo`, строки «Камер в зоне», пункта нижнего меню. `mediaKinds` и `media` не читаются, `getIncidentMedia` не вызывается. Раскладка — две колонки вместо трёх. Выбор строки по-прежнему подсвечивает путь в дереве, но больше ничего не переключает. Шаг Image с `source: camera|map` не показывает кнопку снимка: шаг необязателен, оператор идёт «Далее». Камеры и снимки — этап 10.
- **165.** Звука нет. Руководство говорит «уведомление со звуком» (раздел 5): строку поправит Task 27, решение пользователя новее. Правила `§8.1` тоже говорят «со звуком», а `§17` записывает это как отступление прототипа; правила не меняем, расхождение Task 27 называет в итоге этапа (вопрос 9).
- **166.** Поля шагов — `StepPlayer` из `features/step-player`, новый необязательный проп `chrome?: 'card' | 'bare'`. `bare` убирает обёртку `Card`, заголовок и низ, остаётся поле; внутри проп идёт контекстом, потому что пять проигрывателей вызывают карточку с явным списком пропов. Значение по умолчанию `'card'`: предпросмотр не меняется. `bare` убирает и описание шага, поэтому `step.description` под заголовком рисует лента Task 12: там текст регламента. Свои поля оператора — там, где проигрыватель не подходит: Message (кнопка в шаге), Image (вложение), Checkbox с одним вариантом (`.confirm-btn`), Comment с `readonly` (текст). Почему: 40-plan требует общие проигрыватели, а заголовок, «Далее» и лента у карточки свои.
- **167.** Вложение Image с `source: operator` — файл в `dataBase64` одним `attachments` запроса, как `app.js`. Предел размера не вводим: контракт его не задаёт. Вопрос 5 ниже.
- **168.** Меню справки показывает только адреса `http:`, `https:` и пути с `/`. `demo:doc/…` эталонного набора скрыт: `SITEMAP.md` — «в продукте окон документов нет». Нет ни одной ссылки — нет кнопки. На встроенном сервере меню поэтому не видно, его проверяет только Vitest. Заодно закрыт `javascript:` в адресе.
- **169.** Экрана настроек администратора нет: пункта меню нет, `incident:schema:admin` не читаем. Шаги самопроверки о нём не повторяются. Почему: в списке экранов пользователя его нет, операции схем отложены.

*Проверка*

- **170.** Сверка с прототипом — автоматическая и глазами. `check-operator-screens.mjs` открывает новый экран и прототип в одном виде, снимает оба в обеих темах и сравнивает вычисленные стили пар элементов из таблицы `PAIRS`: `background-color`, `color`, `font-size`, `font-weight`, `border-radius`, `height` ±2 px. Элементы нового экрана отмечены `data-op="<имя>"`. Глазами — пары снимков и сданные снимки `prototype/shots/` из таблицы Task 4, обязательный шаг Концовки, п. 3. Сравнивать целый кадр пикселями нельзя: у прототипа есть видео, а центр шире. Для экранов без сданного снимка свежий снимок прототипа и есть образец. Образцу нужна его тема: `sync-im-proto.sh` с Task 2б копирует и `theme`, иначе все `--one-*` прототипа на стенде пусты.
- **171.** Встроенный сервер получает адрес `?colleagues=off`: снимки и проходы идут без эмуляции коллег, иначе очередь меняется под руками. Поток проверяет сцена с коллегами. Только в разработке, как `?api=embedded`. Прототип такого адреса не знает: скрипт снимков глушит у него коллег сам (`evaluateOnNewDocument`, Task 4), сам прототип не меняется.
- **172.** Часть 4 защищена дважды. Сервер запускает поток сервера, не этот этап. `check-operator-server.mjs` делает записи только при `IM_STAND_WRITES=1`, а контролёр ставит его, когда пользователь разрешил записи в `imdb`. Без него скрипт сверяет только чтение; любое чтение тоже пишет `Directory.Remember` (решение 137), поэтому и он идёт только по слову контролёра.
