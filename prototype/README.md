## Логика: встроенный сервер и машина состояний

Прототип устроен как продукт: интерфейс разговаривает только запросами из контракта [`openapi.json`](../Specification/State_machine/openapi.json), а отвечает ему встроенный сервер в той же вкладке. Сервер исполняет машину состояний [`workflow.v4.json`](../Specification/State_machine/workflow.v4.json). Своей таблицы переходов у прототипа нет. Сеть не нужна: страница открывается и с диска, и с сайта.

```
app.js     интерфейс: только запросы API — api.get("/operator/incidents?filter=open"), api.post(…/transitions/claim)
   ▼
api.js     клиент API: по умолчанию — во встроенный сервер, с ?api=https://… — на настоящий бэкенд
   ▼
server.js  встроенный сервер: маршруты openapi.json, инциденты, журнал, сессия, планировщик, поток событий
   ▼
engine.js  исполнитель машины: действия, переходы, формы, бейджи, нормативы, автоматические переходы
```

| Файл | Роль |
|---|---|
| [`app.js`](app.js) | Интерфейс. Своих данных нет: всё — из ответов API. Рисунки кадров камер и планов — заглушки картинок видео- и картоподсистемы: сервер ссылается на них как `demo:scene/<имя>` и `demo:plan/<имя>`, обычную ссылку интерфейс показывает картинкой |
| [`api.js`](api.js) | Клиент API. Встроенный режим — запрос в `server.js`, внешний (`index.html?api=https://…`) — HTTP и поток событий SSE к бэкенду; бэкенд должен разрешать запросы со страницы (CORS) |
| [`server.js`](server.js) | Встроенный сервер: отвечает по `openapi.json`, хранит инциденты, журнал, ответы сценария и сессию, раз в секунду выполняет автоматические переходы, эмулирует коллег, шлёт поток событий |
| [`engine.js`](engine.js) | Исполнитель машины — его вызывает только сервер |
| [`colleagues.js`](colleagues.js) | Настройки эмуляции коллег для живости демо. Коллеги действуют через переходы машины от своего имени; проверяет это тест в `tests/api-scenarios.js` |
| [`workflow.js`](workflow.js), [`openapi.js`](openapi.js), [`fixture.js`](fixture.js) | Машина, контракт и эталонный набор данных [`fixtures/demo.json`](../Specification/State_machine/fixtures/demo.json), собранные скриптом `tools/build_workflow.py`: из `file://` браузер не читает JSON. Руками не правятся |

После правки машины или контракта — `python3 tools/build_workflow.py`, затем самопроверка `index.html?selftest`: она проходит переходы через интерфейс и сверяет ответы встроенного сервера со схемами `openapi.json`. Правила модели без интерфейса, с управляемым временем и случайными прогонами, проверяют тесты API — [`../tests/api.html`](../tests/api.html). Что правила не продублированы в коде прототипа, проверяет `python3 tools/check_mutations.py`.

## Диагностика (§0)

- Слой переменных: `:root` / `[data-theme=light]` / `[data-theme=dark]`, ~72 переменные.
- Hex всего 113, цветов числами вне блока темы — 13 (8 hex и 5 rgba): HUD камеры (подписи и подложки кнопок, виньетка), белый значок маркера источника на карте, светлая подложка и легенда схемы эвакуации, белая цифра счётчика на нижней панели телефона. Не трогались (§2.11).
- `--badge-foreign-border` в потреблении — **фон** бейджа «чужой», не рамка. Маппинг по роли, не по имени.
- Состояния с цветом: `.active`, `.selected`, `.on`, `[aria-pressed]`, `.current`, `:hover`, `:focus-visible`, `.trace` / `.trace-leaf`, `option:checked`.

Скриншоты оригинала: `shots/original-dark.png`, `shots/original-light.png`.

## Что сделано

Переменные переведены на `--one-*` по таблице §1. Поверх — правила, которые переменные не выражают:

- эскалация красная (`venetian-red` → `red`), перенаправление оранжевое — UX этого прототипа (D-010, D-012), не правило кита;
- выделение дерева и навигации только фоном (D-011);
- рамки контролов 1px (D-014);
- focus ring 2px вместо мягкого 4px-ореола (D-015 / §2.6);
- лестницы primary / outline / subtle / ToggleButton / ComboBox-опций — дословно из §2.8–2.9;
- включённые кнопки панелей и сегмент Архив/Online — primary, не нейтральный selected (D-018);
- кнопка темы исключена из ToggleButton: это действие со сменным глифом;
- hover карточки очереди — половинный (D-019);
- бейдж чужого владельца — рецепт D-020 (light 8.7:1, dark 7.6:1);
- заголовки панелей `heading-sm`, диалогов `heading-md` (D-021);
- знак приложения — ONE-sign маской на существующем `.brand-mark` (D-023);
- границы регионов в Dark — `--one-border` (D-024).

## Решения, которые принял сам

1. **Взял цветовую политику пилота IM из кита** (оранжевая передача, grape/lavender для «чужого»). Красный/оранжевый раскол escalate/redirect снят в v3: одна кнопка «Передать». D-016 запрещает обобщать палитру на другие прототипы, но для IM владелец уже зафиксировал D-010.
2. **Радиусы** свёл к `--one-radius-window` / `--one-radius-container`. D-004 разрешает оставить геометрию прототипа; свёл, чтобы карточки и поля читались одной семьёй. Можно откатить двумя строками в `bridge.css`.
3. **Заголовок диалога** поставил на `heading-md` — в §2.2b это явно, в пилоте кита диалоги ещё не смотрели.
4. **Ореол полей** (4px `accent-ring` на `:focus`) заменил, не дополнил, focus ring’ом — так написано в §2.6.
5. **Скриншоты** сняты `scripts/shots.mjs` кита через установленный Edge (`PLAYWRIGHT_CHROMIUM_CHANNEL=msedge`): CDN Playwright Chromium с этой машины не скачивается.

## Пробелы §2.8 — лестницы нет, не выдумывал

Оставил как в прототипе (плюс то, что уже даёт маппинг переменных):

| Контрол | Что есть сейчас | Почему не трогал |
|---|---|---|
| Пункт меню (`.menu-item`, не `<select>`) | hover = `--panel-2` | Нет лестницы меню |
| Чекбокс очереди, radio/check-строки сценария, `.confirm-btn.on` | нативные / 1px рамка; `.on` по-прежнему soft-accent | Нет лестницы checkbox/radio |
| Текстовое поле, textarea, search | 1px + focus ring | Нет лестницы editor hover/typed |
| Чипы `.chip.lvl` / `.chip.grp` | цвет из уже замапленных `--esc-*` / `--badge-foreign*` | Нет лестницы chip |
| Шаги сценария `.crumb.current` | номер и подпись в accent | Это не дерево и не кнопка; §2.3 их не перечисляет |
| `.btn.danger` (Перехватить), `.btn.ok` (макрос запущен) | тройки feedback | У Button нет danger/success appearance |
| Обёртка языка `.lang:hover` | рамка accent | Не ComboBox-опция и не кнопка |
| Тики камеры `.cam-tick.active` | заливка accent | Нет лестницы pager-dots |

Это полезный результат эксперимента: словарь закрывает кнопки, toggle, select и панели; форма сценария, меню и чипы в правилах ещё не описаны.

## На подтверждение владельцу

- Радиусы ONE вместо 12/10px прототипа — оставить или вернуть.
- Кнопка «Передать» везде оранжевая (`warn` / `--esc-*`): очередь, карточка и форма. Отдельный красный для escalate снят.
- Плашки очереди: фон `--panel` на колодце `--bg` (canvas), рамка `--stroke-2`, радиус `--radius` (window). Сдвиг при наведении, без него при `prefers-reduced-motion`. Кнопки справа колонкой одной ширины, всегда видны. Hover-reveal из внешнего макета не брали: очередь должна работать на телефоне.
- Невыбранный rest ToggleButton в DS — boxed `editor-bg`; шапка и Архив/Online остаются плоскими, как в принятом пилоте.
- D-019 (половинный hover карточки) по-прежнему предварительный.
- Не ходил вручную: карточка сценария, мобильная ширина, дерево (кроме выбранной строки), пейджер, макросы.

## Как смотреть

Сервер от корня репозитория (чтобы `../theme/one-psim.css` резолвился):

```text
npx http-server . -p 4173 -c-1
```

Открыть `http://127.0.0.1:4173/prototype/index.html`. Повтор снимков: `prototype/shots/_run.ps1` — нужны клон кита рядом с этим репозиторием (или путь в переменной `ONE_PSIM_KIT`), Node и Edge.

Снимки состояний `state-*` сняты до того, как прототип перешёл на машину состояний, и ждут повторного прогона скрипта: на `state-warn-*` и `state-card-hover-*` — прежняя кнопка «Эскалация». Снимка формы передачи `state-dialog-transfer-*` ещё нет. Снимки «Перенаправить» и формы эскалации удалены: этих кнопок больше нет. Главные экраны `restyled-*` пересняты 2026-10-03 в headless Chrome.
