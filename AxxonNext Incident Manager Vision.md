**1. Клиентская часть (****Web****-интерфейс и кроссплатформенность)**

**1.1. Архитектура и среда**

•             Работа с внешним ПО (AxxonNext, Intellect,…) осуществляется через API с плагинным механизмом

•             Работа клиентской части под любым современным браузером (web-based и кроссплатформенность).

•             Поддержка HTTPS и безопасной аутентификации для защиты от несанкционированного доступа.

**1.2.** **Основной функционал**

•             Возможность оператору обрабатывать инциденты по заранее запрограммированным сценариям

•             Возможность просмотра видео (архив) и открытия карты с местом сработки инцидента (п.3)

•             Поддержка гибкой системы прав доступа (собственная), позволяющая назначать разные уровни прав (оператор, старший смены, администратор и т.п.).

•             Возможность обмениваться событиями между операторами (эскалация)

•             Возможность «перехвата» события, обрабатываемого оператором, с сохранением статуса всех проделанных по сценарию шагов

•             Возможность удаленного отслеживания статуса обработки события (контроль оператора)

**1.3.** **Группировка**

•             Группировка событий, типы группировок – по региону, по типу события, по типу объекта. Кастомная группировка (указание списка объектов, которые будут обрабатываться как единый)

•             Групповая обработка событий (как одно)

**1.4. Кастомизация интерфейса**

•             Возможность гибкого настраивания состава панелей, их расположения и размеров «под себя».

•             Настройка «горячих клавиш» под себя

•             Настройка «времени отдыха» (обеда), когда события не поступают или отображается соответствующий статус

•             Настройка меню с вспомогательными ссылками (открытие любых ссылок типа файлов, веб-страниц и т.д.), например с номерами телефонов, фамилий ответственных лиц и т.д.

**1.5. Типы панелей**

•             Панель групп (если включена группировка)

•             Панель событий

•             Панель обработки (по сценарию)

•             Карта

•             Видеомонитор (для просмотра архива)

•             Дашборды (нужны ли?)

**2. Серверная часть (диспетчер событий)**

2.1. **Хранение событий, которые должны быть обработаны**

•             Диспетчер событий создается в ITV DataCenter

•             В плагинах нужно реализовать механизм получения списка объектов и событий, которые будут выбираться в фильтрах

•             Удаленная настройка (выбор) серверов, являющихся источниками событий

•             Настройка таймеров и правил автоэскалации

**3. Работа с видеопотоками и картой (+ связи камер)**

2.1. **Встроенный веб****-****видеоплейер**

**4. Отчётность (****AxxonData****)**

6.1. **Формирование отчётов и статистики**

•             Должна быть интеграция, в которой серверная часть будет отправлять результаты работы оператора в AxxonData

•             Возможность генерировать отчёты в веб по инцидентам за определённый период, по типам и статусам, со сводными диаграммами, по географической распределенности.

•             Возможность включать в отчет кадры со связанных камер и скриншот Карты с местом инцидента.

•             Сегментация отчётов по операторам, локациям, типам инцидентов, времени реакции и т.д. Определение среднего времени реакции/обработки ивентов операторами (сводные отчеты).
