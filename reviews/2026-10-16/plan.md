## Этап 2. Решения

| Номер | Вопрос | Варианты | Предложение | Решение | Кто, дата |
|---|---|---|---|---|---|
| RULE-83 | Что делать с переходом по таймеру, если в окне после дедлайна выполнено ручное действие, после которого таймер продолжается («Передать», «Отклонить» — реакция)? | а) окно отменяет переход по таймеру, только если ручное действие таймер останавливает или запускает заново. Если таймер продолжается (`continuesOn`), отмены нет: переход по таймеру выполняется сразу после ручного, уже из нового состояния. Передал в окне — тут же автоэскалация, как при передаче за секунду до дедлайна; б) ручной переход в окне запускает продолжающийся таймер заново по нормативу уровня: адресат получает полный срок — но передачей в окне можно продлить реакцию, против RULE-76 и RULE-82; в) запретить «Передать» и «Отклонить» в окне — ответ 409 | а): исход не зависит от того, попала ли передача в окно; окно защищает действие, которое заканчивает ожидание («Взять», «Принять», «Закрыть»), а не продолжает его. Стоимость: §10.1, правило 5, `$comment` `invariants.manualWinsOverTimer`, README машины; исполнитель (`overridden` — пропускать переходы из `continuesOn` таймера); тест API, мутация | | |
| RULE-84 | Что с реакцией, если она уже остановлена потолком эскалации или нарушением, а инцидент передают или отклоняют? | а) записать то, что делает машина: «Передать» запускает реакцию по нормативу уровня — новый адресат получает срок, по истечении снова потолок или нарушение с алертом; «Отклонить» не запускает — отклонённый ждёт человека, как после потолка; б) «Передать» тоже не запускает: после потолка инцидент без срока, пока его не возьмут; в) «Отклонить» тоже запускает по нормативу уровня — отклонённый в очереди снова со сроком | а): передача — решение человека, новому адресату нужен срок, иначе о его бездействии никто не узнает; отклонение возвращает в ту же очередь, где потолок уже сработал. Стоимость: §4, §6.1, README машины, тест API | | |
