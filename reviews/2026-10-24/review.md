## 2. Ошибки в прототипе

- **BUG-117** [средний] *архитектор, тестировщик, разработчик* ✅ **Правило BUG-105 — только во встроенном сервере, контракт говорит обратное.** Сервер не шлёт `incident.card_evicted`, пока выполняет переходы, вызванные своим перерывом или выходом ([server.js:325](https://github.com/soulhome2/IM/blob/535dda9/prototype/server.js#L325), `:1336`, `:1345`). В машине у `system_hold_break` и `owner_signed_out` эффект `evictOpenCard` остался ([workflow_schema.v1.json:890](https://github.com/soulhome2/IM/blob/535dda9/Specification/Workflow_machine/workflow_schema.v1.json#L890), `:995`), а контракт среди причин события по-прежнему называет «перерыв, выход» и шлёт его «тому, у кого она открыта» ([openapi.json:5791](https://github.com/soulhome2/IM/blob/535dda9/Specification/Workflow_machine/openapi.json#L5791)). У системного перехода `actor` — система, для клиента это чужое действие ([app.js:4235](https://github.com/soulhome2/IM/blob/535dda9/prototype/app.js#L4235)): бэкенд по контракту пришлёт событие за свой перерыв, и клиент покажет «карточка только для просмотра» — ровно исходная ошибка. README машины ([README.md:378](https://github.com/soulhome2/IM/blob/535dda9/Specification/Workflow_machine/README.md?plain=1#L378)) этого не уточняет, правила клиента «есть `observerNotice` для всех — второго уведомления нет» нет в `FRONTEND.md`.

  Выход тестами не защищён: тест API BUG-105 проверяет только перерыв ([api-scenarios.js:575](https://github.com/soulhome2/IM/blob/535dda9/tests/api-scenarios.js#L575)), шаг самопроверки «Свой выход…» ловит поломку только если она и на сервере, и на клиенте. Порча «на выходе `runScheduler()` вместо `runSchedulerForOwnChange()`» проходит все тесты API и самопроверку. Правило записано в коде прототипа, а не в машине.

## 4. Противоречия и пробелы в правилах

- **RULE-129** [средний] *архитектор, тестировщик* ✅ **Срок «Нет связи» — число, а не «порог возврата минус порог удержания».** Правила ([States rules IM.md:136](https://github.com/soulhome2/IM/blob/535dda9/Specification/State_rules/States%20rules%20IM.md?plain=1#L136), `:258`, `:329`) и комментарий машины связывают срок с порогами, в машине — постоянная `maxMinutes: 15` ([workflow_schema.v1.json:206](https://github.com/soulhome2/IM/blob/535dda9/Specification/Workflow_machine/workflow_schema.v1.json#L206)), пороги настраиваются отдельно (`session.idleHoldSec`, `idleReleaseSec`), сверки нет. Запуск: порог возврата 60 минут, оператор молчит — `system_hold_idle` на 5-й минуте, `no_link_hold_release` на 21-й, возврат по молчанию не срабатывает никогда. При настройках по умолчанию (1200 − 300 = 900 с) всё сходится. Тест «порог возврата хоть час» ([api-scenarios.js:1386](https://github.com/soulhome2/IM/blob/535dda9/tests/api-scenarios.js#L1386)) принимает любой из двух переходов и расхождение не ловит.
