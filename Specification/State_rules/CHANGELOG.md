## v10: что изменилось относительно v9

Решения ревью 2026-10-15 — 2026-10-16, после передачи разработчикам (тег `handoff-1`): эскалация и реакция без обнуления передачами, окно после дедлайна для передачи, отклонения и объединения, «Посмотреть» без права на просмотр, дерево групп по устройству-источнику — с клавиатурой и поиском, нижний ряд кнопок карточки. Новая точка передачи — тег `handoff-2`.

### Что сделать разработчикам с `handoff-1`

Только то, что меняет реализацию. Тексты, описания и демо-данные — в таблице ниже.

**Бэкенд и исполнитель машины**

- Уровень эскалации (`escalation_level`) меняет только автоэскалация. Ручная передача — `transfer_count` + 1 (RULE-76).
- Реакция: «Передать» из `new` и `pending_acceptance` и «Отклонить» её продолжают, а не запускают заново (`continuesOn`, `startTimer … ifStopped`); из `in_progress` и `on_hold` «Передать» запускает её по нормативу текущего уровня. Если реакцию уже остановил потолок или нарушение, «Передать» её запускает, «Отклонить» — нет (RULE-76, RULE-82, RULE-84).
- Окно после дедлайна: ручной переход из `continuesOn` таймера срабатывание не отменяет — переход по таймеру выполняется по окончании окна, из нового состояния (RULE-83). «Взять в работу одним» проверяет окно у каждого привязанного и у основного, как одиночный переход: отменённое — запись в журнале и нарушение на момент дедлайна (BUG-62).
- «Перехватить» — только не адресату: условие `isNotTarget` (BUG-55).
- Права `incident:read:any` нет: карточку открывает любой, кому виден инцидент (RULE-81).
- Инцидент относится к группе и устройству по устройству-источнику: фильтр очереди по группе, счётчики дерева, нормативы по группе устройств (RULE-85).
- «Взять в работу одним»: основной — самый срочный из своих в работе, при равенстве — самый старый; у основного «Ожидает принятия» отсоединять можно только после «Принять» (RULE-78).
- У состояний сессии нет `assignsNewIncidents` — его никто не читал (RULE-77).

**Контракт `openapi.json`**

- У инцидента — `transferCount`; описан `escalationLevel` (RULE-76).
- У действия — `style: icon` и поле `icon` (RULE-81).
- У `GET /operator/incidents/{incidentGuid}` нет ответа 403 (RULE-81).
- Описаны `mediaKinds` (DATA-07), `sourceGroupGuid` и `counters` — по устройству-источнику (RULE-85).
- Бейдж чужого «В работе» — ключом каталога `workflow.badge.in_progress.other` (BUG-51).

**Фронтенд**

- «Посмотреть» — значок «глаз» слева от названия у каждого инцидента очереди, вместо «Открыть» и «Просмотр» (RULE-80, RULE-81).
- Дерево групп: в группе все её устройства, число — у устройства с открытыми инцидентами; клавиатура как у дерева WAI-ARIA; поиск — выделение совпадения, «Найдено: N», «2 / 5» и ▲ ▼ (RULE-86, RULE-88).
