# Памятка для команды бэкенда

С чего начать операторскую часть МИ и как понять, что она готова. Подробности — в [README машины](README.md), здесь — порядок работы и критерий готовности.

## Что реализовать

| Что | Где описано |
|---|---|
| REST API операторского места — 35 операций, плюс 2 служебные для тестового стенда | [`openapi.json`](openapi.json) — контракт, OpenAPI 3.1 |
| Исполнение модели workflow: 5 состояний, 21 переход, 26 условий, 20 эффектов, таймеры, лимиты, права | [`workflow.v4.json`](workflow.v4.json) — модель как данные; смысл — в [README машины](README.md), «Модель workflow» |
| Правила, из которых всё это следует | [`States rules IM.md`](../State_rules/States%20rules%20IM.md) — действующие правила, ссылки «§N» ведут туда |

Модель — это конфигурация, а не код. Сервер хранит её, исполняет и отдаёт клиенту (`GET /operator/workflow/active`). Переходы, кнопки, формы, бейджи и нормативы клиент берёт оттуда и из ответов сервера. Своей таблицы переходов у клиента нет.

Образец исполнения — встроенный сервер прототипа: [`prototype/server.js`](../../prototype/server.js) и исполнитель модели [`prototype/engine.js`](../../prototype/engine.js). Это JavaScript в браузере, в продукт его не переносят, но по нему видно, как понимать каждое условие и эффект.

## На что обратить внимание

- **Переход атомарен.** Всё меняется одним запросом `POST …/transitions/{transitionId}` в одной транзакции: состояние, владелец, таймеры, журнал. Отдельных `/claim`, `/close` нет и не будет.
- **Версия записи.** Карточка отдаёт `ETag` — поле `version` в кавычках, `"12"`. Переход и ответы сценария приходят с `If-Match`. Нет заголовка — `428`, версия не совпала — `412` с актуальной карточкой в теле.
- **Ошибки** — `application/problem+json` с машинным `code`. Перечень кодов — `Problem.code` в контракте, какое условие даёт какой код — в README машины, «Коды ошибок перехода».
- **Таймеры живут на сервере.** Дедлайны — метки времени. Автоэскалацию, нарушения нормативов и потерю связи выполняет планировщик сервера, клиент только показывает отсчёт.
- **Поток событий обязателен** — `GET /operator/stream`, SSE. Сообщение без строки `event:`, в `id:` — `id` события, в `data:` — JSON. Сервер досылает пропущенное после `Last-Event-ID`.
- **Признак активности.** Клиент шлёт `heartbeat` раз в `session.heartbeatSec`. Если его нет `idleHoldSec`, инцидент оператора уходит в «Отложен — нет связи», через `idleReleaseSec` — обратно в очередь (§12.3).
- **Идентификаторы.** У инцидентов, устройств, групп устройств, типов событий, планов и сценариев — UUID, номер для показа — `number`. Люди и дежурные группы — строки внешней системы (§5).
- **Записи журнала** хранятся шаблоном и подстановками (`templateKey` + `vars`): клиент переводит их на язык оператора.

## Тестовый стенд

Бэкенд проверяется тем же набором тестов, что встроенный сервер прототипа. Для этого стенду нужны две служебные операции (тег `test-support`). В боевой сборке их быть не должно.

1. **`POST /test/reset`** загружает эталонный набор [`fixtures/demo.json`](fixtures/demo.json) и по умолчанию останавливает часы. Время в наборе абсолютное, при загрузке сдвигается на «сейчас − `capturedAt`». Таймеры заданы моментом запуска, длительность — из модели. Формат набора — README машины, «Тестовый стенд».
2. **`POST /test/clock`** сдвигает часы и сразу выполняет всё, что за это время должно сработать.
3. **CORS для страницы тестов:** разрешить заголовки `Content-Type` и `If-Match` и `credentials`, открыть странице `ETag` (`Access-Control-Expose-Headers`). Страница, открытая с диска, приходит с `Origin: null`.

Прогон: открыть `tests/api.html?api=https://адрес-стенда` в браузере. Тесты проходят сценарии по правилам и случайные прогоны с инвариантами, сверяют каждый ответ со схемами контракта (поля, типы, форматы, обязательные заголовки) и проверяют, что вызвана каждая операция.

Клиентская сторона этого пути уже проверена: те же тесты проходят по сети против встроенного сервера (`python3 tools/check_loopback.py`). Если на стенде что-то падает, причину стоит искать на стороне бэкенда, в CORS или во входе.

## Когда готово

- `tests/api.html?api=…` — все тесты зелёные, строка «Каждая операция контракта покрыта тестами» — тоже.
- Прототип работает с бэкендом: `prototype/index.html?api=https://адрес` — очередь, карточка, переходы, поток событий.

Тесты не проверяют операции редактора схемы (`/operator/workflow/schemas…`, 7 операций): экрана редактора пока нет. Их проверка — отдельно.
