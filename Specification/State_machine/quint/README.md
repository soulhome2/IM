# Формальная модель машины состояний на Quint

`im.qnt` — модель машины [`workflow.v4.json`](../workflow.v4.json) на языке [Quint](https://quint-lang.org). Смысл условий и эффектов — как в исполнителе прототипа [`prototype/engine.js`](../../../prototype/engine.js). Модель не заменяет машину: она проверяет её правила на маленьком мире — 2 инцидента, 2 оператора, 1 дежурная группа — перебором путей, отдельно от кода прототипа.

| Файл | Что это |
|---|---|
| `im.qnt` | Модель: состояние инцидента, переходы — условие `<id>Ok` и действие с эффектами, действия окружения (наступление дедлайнов), инварианты |
| `im_test.qnt` | Сценарии: права и настройки заданы, шаги по порядку, в конце — инварианты |
| [`tools/check_quint.py`](../../../tools/check_quint.py) | Модель не разошлась с машиной: переходы, «откуда» и «куда», условия, эффекты, справочники |

## Что моделируется

Ядро — 18 переходов: `create`, `claim`, `accept`, `reject`, `hold`, `resume`, `release`, `transfer`, `takeover`, `close`, `reopen` и переходы по таймерам `auto_escalate`, `escalation_ceiling`, `reaction_overdue`, `resolution_overdue`, `resolution_escalate`, `resolution_ceiling`, `hold_overdue`.

Права, доступ к объектам, состав дежурной группы и настройки (`escalation.enabled`, `escalation.onResolutionOverdue`, `maxActive`, `maxOnHold`) выбираются при старте произвольно, поэтому симуляция перебирает и конфигурации. Уровни эскалации: 1 — человек, 2 — группа, `maxLevel` = 2, как в машине. `maxOnHold` в модели — 1 или без ограничения, чтобы лимит достигался.

Время абстрактное. У таймера фаза: `Before` — дедлайн впереди, `Due` — наступил и ещё не сработал (`timerExpired`), `Fired` — сработал: каждый дедлайн срабатывает один раз (`firedTimers` прототипа). Дедлайн наступает действием окружения `expire*`.

**Пока не моделируется:** состояние оператора (все `ready`, `agentReady` выполнено), системные переходы, `merge` / `linked`, смена прав и доступа, окно `manualWinsOverTimer` — без него переход по таймеру срочный: пока он возможен, ручные действия над инцидентом ждут, как при `graceSec` = 0. Не моделируются и журнал, уведомления, внешние команды, сценарий (шаги `closing` — флаг «заполнены»), `version`, конкретные секунды. Переходы машины вне модели перечислены в `NOT_MODELED` скрипта `check_quint.py`.

## Инварианты

| Имя | Что проверяет |
|---|---|
| `ownerByState` | Владелец по состоянию: `new` — ни владельца, ни группы; `pending_acceptance` — ровно одно из двух; `in_progress`, `on_hold` — владелец-оператор без группы; `closed` — владелец — закрывший (§2.1) |
| `holdReasonIffOnHold` | Причина удержания задана тогда и только тогда, когда `on_hold` |
| `timersByState` | Идёт таймер состояния, `resolution` в `pausedInStates` на паузе, в `closed` ничего не идёт; реакция в `new` / `pending_acceptance` остановлена только после записанного нарушения (RULE-84); сработавшая реакция не идёт дальше |
| `levelBounded` | `0 ≤ escalation_level ≤ maxLevel` (§8.3) |
| `closeResultIffClosed` | Результат закрытия задан тогда и только тогда, когда `closed` (§2.2) |
| `timerTransitionsExclusive` | По инциденту готово не больше одного перехода по таймеру (§14.3) |
| `dueDeadlineHandled` | Наступивший дедлайн идущего таймера кто-то обрабатывает — не теряется молча (§4, §9) |
| `limitsRespected` | В работе у оператора не больше `maxActive`, отложенных — не больше `maxOnHold` (§10.2) |
| `pendingAddresseeCanAccept` | У ожидающего принятия адресат может принять (§8.1) |
| `autoEscalateNotToCurrentAddressee`, `resolutionEscalateNotToCurrentAddressee` | Эскалация — по реакции и по нормативу закрытия — не адресует инцидент тому, у кого он уже есть: тому же человеку, той же группе или группе, где принять может только владелец (§8.3, RULE-93) |
| `inv` | Все вместе |

## Как запустить

Нужен Node.js 18 или новее. Без прав администратора — в домашнюю папку:

```bash
# архив Node.js LTS с nodejs.org → ~/.local/opt/node, затем
export PATH=~/.local/opt/node/bin:$PATH
npm i -g @informalsystems/quint
```

Из этой папки:

```bash
quint test im_test.qnt                                   # сценарии, меньше секунды
quint run im.qnt --invariant inv --max-samples=10000     # 10 000 случайных трасс по 20 шагов, около 20 секунд
quint run im.qnt --invariant inv --max-steps=80 --max-samples=20000   # длиннее, около полутора минут
```

Из корня репозитория — без Quint, нужен только Python:

```bash
python3 tools/check_quint.py
```

`quint run` — случайная выборка трасс, а не полный перебор. Полный перебор до заданной глубины — `quint verify im.qnt --invariant inv` через Apalache, ему нужна Java 17 или новее.

## Если инвариант нарушен

`quint run` печатает трассу-контрпример: состояния по шагам, в `lastAction` — какой переход, кто и над каким инцидентом. Повторить — по `--seed` из вывода. Дальше выяснить, где ошибка: в модели (перенесли правило не так — сверить с машиной и `engine.js`) или в машине (правило допускает такое состояние). Ошибку машины правят в `workflow.v4.json`, затем модель и `python3 tools/check_quint.py`.

## Когда меняется машина

`python3 tools/check_quint.py` покажет, что разошлось. Новое условие или эффект, которого нет в таблицах скрипта, — тоже ошибка: дополнить таблицу (`guard_atom`, `effect_token`) и модель. Новый переход — смоделировать или добавить в `NOT_MODELED`.
